The `h0x` CLI talks to a running h0x-ADE runtime. Use it when a shell script or agent needs to inspect worktrees, launch terminals, open files, automate the built-in browser, or report progress back into h0x-ADE.

## Verify the runtime

Register the CLI under [Settings → General → h0x CLI](/docs/settings), then check that it can reach h0x-ADE.

<Callout title="The CLI command is h0x">
  h0x-ADE installs the same `h0x` launcher on every supported platform. It does not install a legacy
  launcher on Linux, avoiding a collision with the GNOME screen reader.
</Callout>

On macOS and Windows:

```bash
command -v h0x
h0x status --json
```

On Linux:

```bash
command -v h0x
h0x status --json
```

If h0x-ADE is not already running:

```bash
h0x open --json
h0x status --json
```

Use `--json` when another tool will parse the result. Human-readable output is for quick terminal checks.

## Selectors

Most commands accept selectors instead of requiring long IDs:

```bash
h0x repo show --repo id:<repoId> --json
h0x worktree show --worktree active --json
h0x worktree show --worktree path:/abs/path/to/worktree --json
h0x worktree show --worktree branch:feature-name --json
h0x worktree show --worktree issue:123 --json
```

`active` and `current` resolve to the enclosing h0x-ADE-managed worktree from the shell's current directory or terminal context. Use explicit selectors in scripts that may run outside the target worktree. For remote runtimes, prefer full server-side selectors such as `id:<repoId>::<absolute-worktree-path>` or `path:<absolute-server-path>` because the local shell's current directory may not exist on the runtime host.

## Choose a host

List every machine the current h0x-ADE host can target and the selector for each one:

```bash
h0x host list --json
```

The result includes this machine, its registered [SSH targets](/docs/ssh), and paired [Remote h0x-ADE Servers](/docs/remote-servers). Use `--host local` for this machine, `--host ssh:<target-id>` for an SSH target, and `--environment <server-name>` for a paired server. SSH rows include the detected remote platform (`linux`, `darwin`, or `win32`) after the target connects; older or disconnected targets report `platform unknown`. They also include `connected` and, when known, the SSH lifecycle `connectionStatus`. SSH labels and paired-server names also resolve when they are unique; use the IDs from `host list` when names collide. If you put a machine name on the wrong selector, h0x-ADE reports the matching machine and the flag to use instead of returning an empty result.

## Runtime commands

```bash
h0x open --json
h0x status --json
h0x serve --port 6768 --pairing-address 100.64.1.20 --json
```

`h0x serve` starts a runtime server in the foreground without opening the desktop window. Use it for [Remote h0x-ADE Servers](/docs/remote-servers) or headless environments, and stop it with `Ctrl-C`.

## Repos

```bash
h0x repo list --json
h0x repo add --path /abs/path/to/repo --json
h0x repo show --repo id:<repoId> --json
h0x repo set-base-ref --repo id:<repoId> --ref origin/main --json
h0x repo search-refs --repo id:<repoId> --query main --limit 10 --json
```

Set the repo base ref before creating lots of worktrees so new tasks branch from the right place by default.

## Worktrees

```bash
h0x worktree list --repo id:<repoId> --json
h0x worktree ps --json
h0x worktree current --json
h0x worktree show --worktree active --json
h0x worktree create --repo id:<repoId> --name fix-login --json
h0x worktree create --name child-task --agent codex --prompt "Investigate the flaky login test" --json
h0x worktree set --worktree active --comment "reproduced failure; testing token refresh fix" --json
h0x worktree rm --worktree id:<worktreeId> --force --json
```

When `worktree create` runs from inside an h0x-ADE-managed worktree, h0x-ADE records the new worktree as a child when it can infer the relationship. Pass `--parent-worktree active` to be explicit, or `--no-parent` when the new work is independent.

Agent startup flags:

```bash
h0x worktree create --name review-api --agent claude --setup run --json
h0x worktree create --name quick-check --agent codex --prompt "Summarize the diff" --setup skip --json
h0x worktree create --name hidden-setup --setup inherit --json
```

`--agent` launches the selected agent in the first terminal. `--prompt` sends initial work to that agent. `--setup run|skip|inherit` controls repo setup hooks; `inherit` follows the repo policy.

## Terminals

```bash
h0x terminal list --worktree active --json
h0x terminal show --terminal <handle> --json
h0x terminal read --terminal <handle> --json
h0x terminal read --terminal <handle> --screen --json
h0x terminal read --terminal <handle> --cursor <cursor> --limit 1000 --json
h0x terminal send --terminal <handle> --text "continue" --enter --json
h0x terminal wait --terminal <handle> --for tui-idle --timeout-ms 300000 --json
h0x terminal create --worktree active --title "tests" --command "npm test" --json
h0x terminal split --terminal <handle> --direction horizontal --command "npm run dev" --json
h0x terminal rename --terminal <handle> --title "runner" --json
h0x terminal switch --terminal <handle> --json
h0x terminal close --terminal <handle> --json
h0x terminal close --worktree active --all --json
```

Omit `--terminal` to target the active terminal in the current worktree. Read before sending when you are not sure what the terminal is waiting for.

Close stops the process as part of removing the terminal. Use `--terminal <handle>` for one
terminal, or `--worktree <selector> --all` to durably close every terminal in exactly that
workspace, including its saved layouts and agent-resume records. Use workspace Sleep when those
terminals should resume later. If the execution host cannot confirm that every PTY stopped, bulk
close returns a failing `unverifiable` result rather than claiming the processes exited.
`terminal stop` remains only for compatibility with older tooling.

<Callout title="Terminal handles">
  Terminal handles are runtime-scoped. If h0x-ADE restarts or a command reports a stale terminal
  handle, run `h0x terminal list --json` and reacquire the handle.
</Callout>

`terminal list` reports each terminal's `executionHostId` when h0x-ADE can verify it, plus a result-level `hostScope` with covered and omitted host IDs. Treat a missing host identity or scope as **unverifiable**, not local. A missing terminal is evidence that it exited only when its execution host is listed in `hostScope.hostIds`.

By default, `terminal read` returns the accumulated output stream with terminal escapes stripped. Programs that redraw lines can therefore appear as stacked fragments. Use `--screen` when you need the currently rendered frame; the response's `source` identifies `stream`, `screen`, or `screen-unavailable`. Screen reads have no history to page, so `--screen` and `--cursor` are mutually exclusive.

For long output, use cursor reads. Save `nextCursor` from one stream read, then pass it back with `--cursor` to fetch only new output.

## Files

```bash
 file open src/App.tsx --worktree active --json
 file diff src/App.tsx --staged --worktree active --json
 file open-changed --mode both --worktree active --json
```

Paths are relative to the selected worktree. `open-changed` reads git status and opens changed files in edit, diff, or both modes.

## Built-in browser

Browser commands control h0x-ADE's embedded browser tab for the selected worktree. They do not control Chrome, Safari, or the h0x-ADE desktop UI.

Use a snapshot -> act -> snapshot loop:

```bash
h0x goto --url http://localhost:3000 --worktree active --json
h0x snapshot --worktree active --json
h0x click --element @e3 --worktree active --json
h0x fill --element @e1 --value "user@example.com" --worktree active --json
h0x wait --text "Welcome" --worktree active --json
h0x screenshot --worktree active --json
```

Refs such as `@e3` come from `snapshot`. Re-snapshot after navigation, tab switches, clicks that change the page, and any stale-ref error.

Tab and capture commands:

```bash
h0x tab list --worktree active --json
h0x tab create --url http://localhost:3000 --worktree active --json
h0x tab switch --index 1 --worktree active --json
h0x capture start --worktree active --json
h0x console --limit 50 --worktree active --json
h0x network --limit 50 --worktree active --json
 full-screenshot --worktree active --json
 pdf --worktree active --json
```

Use `h0x exec --command "<agent-browser command>" --json` only for browser actions that do not have a typed h0x-ADE command yet.

Browser device emulation:

```bash
 set device --name "iPhone 12" --worktree active --json
h0x screenshot --worktree active --json
```

## Desktop computer use

Use `h0x computer` for native desktop apps outside the built-in browser:

```bash

 computer paste-text --app com.apple.Safari --text "hello" --json
```

See [Computer use](/docs/cli/computer-use) for the full workflow and permission setup.

## Mobile emulator

The mobile emulator commands control iOS Simulator devices through h0x-ADE's worktree-scoped bridge. Use them instead of raw `serve-sim` or `simctl` when an agent is operating from inside h0x-ADE, so lifecycle and active-device state stay attached to the current worktree.

```bash
h0x emulator list --worktree active --json
h0x emulator attach "<device-name-or-udid>" --worktree active --json
h0x emulator tap 0.5 0.7 --worktree active --json
h0x emulator type "hello" --worktree active --json
h0x emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --worktree active --json
h0x emulator button home --worktree active --json
h0x emulator rotate landscape_left --worktree active --json
h0x emulator exec --command "tap 0.5 0.7" --worktree active --json
h0x emulator kill --worktree active --json
h0x emulator shutdown --worktree active --json
```

Coordinates are normalized from `0` to `1`. Prefer `tap` for single taps, and use `gesture` for drags or multi-step touch input. Pass `--device <udid-or-name>` or `--emulator <id>` when a script must target a specific simulator instead of the worktree's active emulator.

## Linear

The `h0x linear` surface is what agents use via the `orca-linear` skill (legacy install name `linear-tickets` still works). Prefer `--json`. Linked worktrees resolve with `--current`.

### Read

```bash
h0x linear issue --current --full --json
h0x linear issue ENG-123 --comments --children --relations --activity --json
h0x linear search "auth bug" --workspace all --json
h0x linear list --filter assigned --limit 10 --json
h0x linear list-issues --team ENG --state started --assignee me --json
h0x linear list-issues --query auth --updated-at -P7D --cursor <cursor> --workspace <id> --json
h0x linear team list --json
h0x linear team states --team ENG --json
h0x linear team labels --team ENG --json
h0x linear project list --query launch --json
```

`--full` expands comments, children, attachments, relations, and activity. Section flags (`--comments`, `--children`, `--attachments`, `--relations`, `--activity`) work individually.

### MCP-style write

```bash
# Create or update (omit id/--current to create; requires --team and --title on create)
h0x linear save-issue --team ENG --title "Fix auth" --priority high --json
h0x linear save-issue ENG-123 --state "In Progress" --assignee me --json
h0x linear save-issue --current --project null --due-date null --json

h0x linear relation add ENG-1 --related ENG-2 --type blocks --json
h0x linear relation remove ENG-1 --related ENG-2 --type related --json
```

`save-issue` labels **replace** the full label set (Linear MCP `save_issue` semantics). Literal `null` clears assignee, estimate, due date, project, or parent.

### Field helpers (still valid)

```bash
h0x linear status set --current --to "In Progress" --json
h0x linear assignee set --current --me --json
h0x linear priority set ENG-123 --to high --json
h0x linear estimate set --current --to 3 --json
h0x linear due-date set --current --to 2026-08-01 --json
h0x linear label add --current --label backend --json
h0x linear comment add --current --body "Investigating regression" --json
h0x linear attach --current --url https://example.com/repro --title "Repro" --json
h0x linear create --title "Flaky login test" --team ENG --priority high --json
```

Run `h0x linear --help` or `h0x skills get orca-linear` for the version-matched list. Pass an explicit issue id (e.g. `ENG-123`) when a script may run outside an h0x-ADE-linked worktree.

## Skills (local, no runtime required)

List bundled guides, print a version-matched guide, or install/update hybrid skill packages without the desktop Settings UI:

```bash
h0x skills list
h0x skills get orca-cli
h0x skills get orchestration --full
h0x skills install --skill orca-cli --skill orchestration
h0x skills install --all --dry-run
h0x skills update --all
```

`install` / `update` shell out to the same `npx skills` commands Settings uses. They do not contact the h0x-ADE runtime. See [h0x-ADE skills](/docs/cli/skills#keep-skills-up-to-date).

## Account (host-local runtime)

On a headless host running h0x-ADE (`h0x serve` or the desktop app), add managed Claude/Codex accounts when the remote client cannot use **Add account** (remote runtime scope disables that button):

```bash
h0x account list
h0x account add                 # Claude by default
h0x account add --agent codex
```

`account add` runs `claude login` / `codex login` in **this** terminal on the host, then registers the captured credentials with the local runtime. Codex uses device authorization so the browser can finish on another machine. Run these on the machine that owns the accounts — not through a client-only remote session.

## Artifacts

Publish HTML or Markdown through the signed-in h0x-ADE account. Viewing a public link does not require sign-in; create/list/update/delete do. **Publishing is off by default** — a human must enable **Settings → Artifacts → Allow publishing public artifact links** on the device. There is no CLI flag that grants the gate. `list`, `unshare`, and `delete` stay available so you can audit or revoke links after turning publishing off.

```bash
h0x artifacts share ./report.html --json
h0x artifacts share ./notes.md --json
h0x artifacts update ./notes.md --json
h0x artifacts unshare ./notes.md --json
h0x artifacts list --json
h0x artifacts list --cursor <cursor> --json
h0x artifacts delete <id> --json
```

- Accepted files: `.html`, `.htm`, `.md`, `.markdown`.
- `share` stores the edit token in the active h0x-ADE profile and does not print it. `update` / `unshare` resolve by the same local path and profile that originally shared the file.
- `list` is paged (`nextCursor` → `--cursor`). `delete` takes the artifact id from `list` and does not need the original file.
- Relative HTML assets are not uploaded — share self-contained HTML or absolute asset URLs.
- Denied publish/update fails with `artifact_sharing_disabled`; fix Settings instead of retrying.
- Desktop: open a local HTML or Markdown file and use **Share as artifact**, or manage links from the sidebar **Artifacts** page.

## Automations, environments, and hooks

Scheduled prompts:

```bash
 automations list --json
 automations create --name "Daily review" --trigger daily --time 09:00 --prompt "Review open changes" --provider codex --repo id:<repoId> --disabled --json
 automations run <automationId> --json
```

Remote runtime environments:

```bash
 environment add --name work-laptop --pairing-code "orca://pair?code=..." --json
 environment list --json
 environment rm --environment <selector> --json
```

Agent status hooks:

```bash
h0x agent hooks status --json
h0x agent hooks on --json
h0x agent hooks off --json
```

## Agent habits

- Prefer `--json` for automation and agent calls.
- Prefer selectors over parsing UI labels.
- Read terminal state before sending input unless the next input is obvious.
- Use worktree comments for progress checkpoints. See [Worktree checkpoints](/docs/cli/worktree-checkpoints).
- Use [Orchestration](/docs/cli/orchestration) for tracked multi-agent dispatches instead of ad hoc terminal prompts.
