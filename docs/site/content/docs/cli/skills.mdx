h0x-ADE ships **skills** that agents install into their skill directories. Public install packages are **hybrid discovery stubs**: short `SKILL.md` files that tell the agent _when_ to engage h0x-ADE and how to load the full guide from the running CLI. Command flags live in the binary so they cannot drift from the app version.

## Installable h0x-ADE skills

Use `npx skills add` with the public h0x-ADE repo and the skill name. Default agent setup usually installs `orca-cli`, `computer-use`, and `orchestration`.

## Hybrid stubs vs the live guide

After `npx skills add`, agents see a short stub that says:

1. Resolve the CLI executable for this session (`ORCA_CLI_COMMAND` when supplied, `h0x-dev` in development, otherwise `h0x`).
2. Load the full guide: `h0x skills get <topic>` (or `--full` for the long guide).
3. Prefer `--json` and do not invent flags from memory.

```bash
h0x skills list
h0x skills get orca-cli
h0x skills get orchestration --full
h0x skills get orca-linear --json
```

Add `--json` when an agent needs deterministic output for automation. `skills show` is an alias for `skills get`.

## Keep skills up to date

When h0x-ADE ships a newer skill package than the one installed globally, the app can:

- Show an **update available** nudge (and **Needs attention** when a copy is out of date somewhere the updater cannot safely rewrite).
- Open **Update skills** — list of placements and skip reasons, then run **`npx --yes skills update <names> --global -y`** headlessly (no embedded terminal).
- Keep the run in the **background**: closing the dialog does not cancel it. A status-bar segment shows progress (spinner while running, brief success check, persistent failure until you act). Click the segment to reopen the dialog.
- Surface freshness on **Settings → Agents** for installed skills (global install rail), including **Details** when a row needs review.

Manual equivalent (desktop Settings still shows the same `npx` form):

```bash
npx skills update orca-cli orchestration computer-use --global
```

On headless hosts (SSH, containers, CI, `h0x serve`) with no Settings UI, use the local CLI wrappers — they resolve the same `npx` commands, add non-interactive flags, and do **not** need a running h0x-ADE runtime:

```bash
h0x skills install                                      # list installable names
h0x skills install --skill orca-cli --skill orchestration
h0x skills install --skill orca-cli --agent claude-code,codex
h0x skills install --all --dry-run
h0x skills update --all
h0x skills update --skill orca-cli --dry-run
```

- Default scope is **global** (`--global`); pass `--local` for the current project only.
- `install` targets agents h0x-ADE detects on the host (plus the shared `.agents/skills` directory). Use `--agent <name>[,<name>…]` or `--agent universal` to override; if no agent is detected, `--agent` is required.
- `update` only refreshes skills that are already installed.
- `--dry-run` prints the resolved command; `--json` is only valid with listing / `--dry-run`.

Prefer the in-app updater when h0x-ADE offers it so the same global placements the app scanned get rewritten. Rows marked **Skipped** explain why that skill cannot be updated automatically (for example missing source registration) — fix the placement, then re-check.

## Install and delete from the Skills page

When an in-app install asks for a workspace target, search the picker by workspace name or by kind (**worktree** / **folder**). The agent picker separates directories h0x-ADE always includes from additional agent directories you can select, so you can review the exact installation targets before continuing.

To remove a scanned skill, open its actions menu and choose **Delete…**. For several skills, open the page's **More actions** menu, choose **Delete skills…**, and select the eligible results. h0x-ADE explains why a copy cannot be deleted—for example because it is bundled, plugin-managed, read-only, or outside a removable skill folder—before you confirm. This is separate from **Manage installs**, which manages copies installed from shared links.

## Share private skills between hosts

Open **Skills → Share skills** to publish one skill or a bundle behind one unlisted, revocable link. Publishing requires your h0x-ADE account. Review the included files, scripts, executables, digest, and optional release notes before you publish; each published version is immutable, so later local edits do not silently change what recipients install.

Anyone with an active link can inspect and install the shared skills without signing in, so treat the link like a credential. A recipient reviews the exact version, chooses all or a subset of its skills, then selects global or workspace scope on this computer, a paired h0x-ADE runtime, WSL, or an SSH host. Existing modified skills default to **Keep local**. Use **Skills → Manage installs** to update, roll back, or remove copies h0x-ADE installed, and **Settings → Share Skills** to copy or revoke your active links. Revoking a link blocks future access but does not remove copies already installed.

Agents can publish an explicitly named set from the CLI after you enable the separate, default-off **Settings → Share Skills → Allow agents and the h0x CLI to publish skill links** permission:

```bash
h0x skills installed --json
h0x skills share --skill frontend --skill testing --bundle-name "Team Toolkit" --json
```

`skills installed` returns safe selectors without exposing local paths. `skills share` accepts exact discovery IDs or unambiguous names; it does not accept arbitrary paths or `--all`.

## Discovery sources

h0x-ADE's skill UI scans installed skill homes for Claude, Codex, Agent Skills, and **OMP** (`~/.omp/agent/skills`), so skills placed there show up without a manual symlink.

## Add your own skills

Any repo with a `skills/<name>/SKILL.md` file can be installed via `npx skills add`. Point your agent at internal repos to give it company-specific powers.

## MCP servers

Model Context Protocol (MCP) servers expose external tools to compatible agents. Register MCP endpoints under [Settings → Integrations → MCP](/docs/settings); those tools appear inside agent CLIs that support MCP.
