### Homebrew (macOS)

h0x-ADE is also published as a Homebrew cask, auto-bumped on every stable release:

```
brew install --cask vjk7989/h0x-ade/h0x
```

`brew upgrade --cask h0x` picks up new stable builds. The cask tracks the stable channel — for RC builds, use the GitHub Releases links above or the in-app **Check for Updates** flow described under [Updates](#updates).

## First launch

On first launch h0x-ADE will:

- Ask for access to your home directory so it can add repos.
- Offer to import `~/.claude`, `~/.codex`, and Ghostty terminal settings if present.
- Drop you on an empty landing screen where you add your first repo.

## Updates

h0x-ADE auto-updates by default, tracking the **stable** channel. Stable releases are vetted; **RC (release candidate)** builds ship new features first, often daily.

On Linux, whether h0x-ADE can apply an update itself depends on which package you installed. See [Linux](#linux) before you pick one.

There is no permanent in-app opt-in for the RC channel. Modifier clicks on **Check for Updates** ([Settings → General → Updates](/docs/settings), or the app / Help menu):

| Modifier                                               | Effect                                                                         |
| ------------------------------------------------------ | ------------------------------------------------------------------------------ |
| **Shift+click**                                        | Include the latest **RC** prerelease                                           |
| **Cmd+click** (macOS) / **Ctrl+click** (Windows/Linux) | Latest **perf**-tagged prerelease                                              |
| **Option+click** (macOS only)                          | Pick a **validated local macOS build** that passes h0x-ADE’s compatibility checks |

You can still download any build directly from the [GitHub Releases page](https://github.com/vjk7989/h0x-ade/releases).

<Callout title="Don't like the current update">
  Older versions are always available on the [GitHub Releases
  page](https://github.com/vjk7989/h0x-ade/releases). h0x-ADE will not force-downgrade your worktree data
  if you go back.
</Callout>

## Platform notes

### macOS

Signed and notarized. On first launch, macOS may still ask you to confirm — that's normal for Electron-based apps.

### Windows

The default shell can be set to PowerShell or CMD under [Settings → Terminal](/docs/settings). Most users want PowerShell.

### Linux

Each published release ships three Linux packages — an **AppImage**, a **`.deb`**, and an **`.rpm`** — for both x64 and arm64. They contain the same app. What differs is how updates reach you, so pick on that.

| Package      | Pick it when                                              | Updates                                                           |
| ------------ | --------------------------------------------------------- | ----------------------------------------------------------------- |
| **AppImage** | You want h0x-ADE to update itself, like on macOS and Windows | h0x-ADE downloads and applies the update in place                    |
| **`.deb`**   | You manage software with `apt` on Debian or Ubuntu        | h0x-ADE tells you a version is out and hands you the install command |
| **`.rpm`**   | You manage software with `dnf`, `yum`, or `zypper`        | Same as `.deb`                                                    |

The AppImage has a stable download link per architecture — [`h0x-linux.AppImage`](https://github.com/vjk7989/h0x-ade/releases/latest/download/h0x-linux.AppImage) for x64 and [`h0x-linux-arm64.AppImage`](https://github.com/vjk7989/h0x-ade/releases/latest/download/h0x-linux-arm64.AppImage) for arm64 — and needs `chmod +x` before its first run, because GitHub release assets carry no permission bits. The `.deb` and `.rpm` filenames carry the version and architecture, and the two formats spell architecture differently (`h0x_<version>_amd64.deb` or `_arm64.deb`; `h0x-<version>.x86_64.rpm` or `.aarch64.rpm`), so take those from the [Releases page](https://github.com/vjk7989/h0x-ade/releases) rather than a fixed URL.

#### How updating works

**The AppImage self-updates.** Choose it if you want automatic updates. h0x-ADE checks for a new release, you click **Update**, and it replaces the AppImage in place — the same flow as macOS and Windows.

**The `.deb` and `.rpm` do not self-update.** h0x-ADE still notices the new version and downloads the package, then gives you a **Copy Install Command** button. Copy it rather than retyping it: h0x-ADE resolves every program to an absolute path in a trusted system directory and single-quotes the package path, so what you paste looks like this:

```
/usr/bin/sudo /usr/bin/apt install -- '/home/you/.cache/orca-updater/pending/h0x_1.4.200_amd64.deb'
```

Which package manager appears depends on what your system actually has: `apt`, else `dpkg -i`, for a `.deb`; `zypper`, `dnf`, `yum`, then `rpm -Uvh` for an `.rpm`. The download directory follows `XDG_CACHE_HOME` when that is set and falls back to `~/.cache` when it is not.

**Quit h0x-ADE before you run the command**, then reopen it once the install finishes. You are replacing the files of a running application, and the package manager cannot swap them safely underneath a live process. h0x-ADE deliberately never escalates privileges to do this for you: installing a system package needs root, `h0x serve` runs as an unprivileged user, and a headless machine has no authentication agent to prompt. VS Code and Signal make the same call on `.deb`.

**A distro-managed build is left alone.** If you are running a repackaged h0x-ADE — an AUR build, a Nix derivation — h0x-ADE sees that no package manager it can drive owns this install and stops offering a download it could never apply. It still reports that a new version exists, so you can update the way you normally would.

#### The CLI command is `h0x`

On Linux the [h0x CLI](/docs/cli/reference) installs as **`h0x`**. h0x-ADE does not install a legacy launcher, so it does not shadow existing system accessibility tools.

- The `.deb` and `.rpm` put `h0x` on your `PATH` at install time, as `/usr/bin/h0x`.
- With the AppImage, register the CLI from [Settings → General → h0x CLI](/docs/settings). That installs `~/.local/bin/h0x`.
- Inside h0x-ADE's own terminals, `h0x` resolves to the matching packaged or development build.

Verify the canonical launcher with `command -v h0x`.
